## 二、A 级：必然驳回项（逐条说明）

### A-1　内容本身违规 —— 最核心的问题

《微信小程序平台运营规范》**3.2.4** 原文：

> 小程序的页面内容中，**不能存在测试类内容**；示例：**算命，抽签，星座运势**等。

微信服务市场另有专门的《算卜算运势、算命修改指引说明》，明确写道：

> 小程序涉及提供算卜算运势、算命等内容，**属于平台未允许的内容**，需要整改后再重新提交，否则代码审核环节将面临因内容不符被驳回。

本项目的以下要素会直接命中该条款：

| 位置 | 内容 | 命中理由 |
|---|---|---|
| `app.json` / `index.json` | 标题「科研塔罗牌」 | 名称即占卜品类 |
| `index.wxml` | 「今日一抽」「三张牌阵」+ 🔮 图标 | 抽牌 = 抽签 |
| `draw.wxml` | 「洗 牌 中」动画 | 占卜仪式 |
| `draw.wxml` | 过去 · 现在 · 未来 三张牌阵 | 预测未来 |
| `cards.js` `summaryOf` | 大吉 / 吉 / 小吉 / 小凶 / 凶 六档 | **算运势**，这是最致命的一条 |
| `draw.js` | 分享文案「【科研塔罗 · 今日一抽】」 | 聊天窗口可见的占卜宣传 |

**判定**：即便把名称里的「塔罗」去掉，只要保留「抽牌 + 吉凶档位」，审核依然会以 3.2.4 驳回。吉凶系统不是可以包装的细节，是违规的核心证据。

### A-2　无匹配服务类目

类目库中不存在「占卜 / 塔罗 / 命理」。若强行挂靠「工具 → 信息查询」或「教育 → 兴趣爱好」，会触发 **3.1.3**「实际所提供的服务不得属于尚未开放的服务范围」，以及最常见的驳回理由「小程序内容与所选类目不符」。

### A-3　appid 是测试号

`miniprogram/project.config.json`：

```json
"appid": "touristappid"
```

游客 appid 只能在开发者工具里预览，**不能上传、不能提审、不能发布**。必须换成在微信公众平台注册的真实 AppID。

### A-4　未完成 ICP 备案

自 2023 年 9 月工信部备案新规执行后，小程序未完成备案**无法正式发布**（备案主体须与小程序主体一致）。另需注意：**多数省份通信管理局已关闭个人主体小程序备案入口**，个人主体可选类目也极窄。若要走这条路，建议用个体工商户或企业执照注册。

### A-5　主包超 2 MB

```
assets/cards/   4.9 MB   （78 张牌图）
代码            0.13 MB
合计            5.1 MB
```

微信小程序主包上限 **2 MB**，超了在开发者工具「上传」这一步就会失败，根本进不了审核队列。

## 三、B 级：补齐即可通过项

| 项 | 现状 | 需要做什么 |
|---|---|---|
| 用户隐私保护指引 | 未配置 | 后台「设置 → 服务内容声明」填写。**当前代码只用了 `wx.getStorageSync/setStorageSync`，未调用任何隐私接口**，可声明为「不收集用户信息」，难度低 |
| 用户协议 / 免责声明 | 首页仅一行 `娱乐为主 · 建议为辅` | 增加独立页面，含免责声明、内容来源说明 |
| 客服 / 反馈入口 | 无 | 加一个「意见反馈」按钮（`wx.openCustomerServiceChat` 或复制邮箱） |
| 提审信息 | 未准备 | 功能页面路径（首页 `pages/index/index`）、测试账号、版本描述 |

其他非阻断项：`project.config.json` 里 `urlCheck: false` 建议正式版改为 `true`；`sitemap.json` 全 allow 无问题。

## 四、C 级：内容风控建议

### C-1　可能触发 3.2.3「引发用户恐惧心理」

虽然上一轮已全文正面化，但牌义库里仍有若干硬词，建议在小程序版文案中再做一次软化：

- 宝剑十：「项目彻底黄了」
- 高塔：「实验、代码或结论被推翻」
- 权杖十：「长期超负荷」
- 各牌科研字段中的「延毕」「翻车」「崩」「拒稿」

建议话术：把「会怎样」改成「可以做些什么」，并保留首页那句免责提示。

### C-2　牌图版权与商标

- 图片用的是 Rider-Waite-Smith **1909 年原版**，已进公有领域，使用风险低。
- 「Rider-Waite」字样在部分国家/类别上仍是 US Games 的注册商标，**小程序名称与简介里不要出现 Rider-Waite / RWS 字样**（当前 `index.wxml` 有 `RIDER-WAITE-SMITH` 字样，属于展示，风险低但建议改成「经典韦特体系」或直接删）。

## 五、可走的三条路

### 方案 A：放弃小程序，继续用网页版（推荐）

已经上线的 https://june125.github.io/research-tarot/ 不受微信类目约束，朋友今天就能用。
- 优点：零改动、零风险、已验证可访问
- 缺点：微信内打开外链体验一般（无分享卡片、可能被提示「非微信官方网页」）；github.io 域名若被大量转发存在被拦截的可能
- 补救：后续可换一个已备案的国内域名

### 方案 B：改造为合规的「科研日签」工具小程序

彻底去掉占卜语义，定位成**随机提示卡 / 每日一句**，走「工具 → 效率」或「教育 → 知识科普」类目。改造清单：

| 现在 | 改成 |
|---|---|
| 名称「科研塔罗牌」 | 「科研日签」「实验室自救卡」「组会充电站」——**避免塔罗/占卜/抽签/运势** |
| 今日一抽 | 今日一卡 / 今日提示 |
| 三张牌阵（过去·现在·未来） | 「三个角度」：现状 · 卡点 · 下一步（去掉时间预测） |
| 洗牌动画 + 🔮 | 去掉或换成普通加载动画 |
| 大吉/吉/小吉/小凶/凶 | **删除整个吉凶系统**，改为「今日关键词」或纯解读 |
| 正位 / 逆位 | 保留，但可改称「正向提示 / 提醒提示」以降低占卜味 |
| 首页免责提示 | 保留，并升级为独立《免责声明》页 |

即便如此仍有残余风险：微信对「抽卡」「随机结果」类一直从严，过审率无法保证。且 A-3/A-4/A-5 三项技术门槛仍需全部解决。

### 方案 C：先解决技术门槛，再审

若坚持保留塔罗玩法，至少要先：

1. 注册真实 AppID（个体工商户或企业主体，完成微信认证 300 元/年）
2. 完成小程序 ICP 备案（约 10 个工作日）
3. 解决包体积：三选一
   - 图片压缩：78 张 320px 图压到每张约 20 KB，总计约 1.6 MB（画质可接受）
   - 分包：拆成 3 个子包，每包 ≤ 2 MB
   - CDN：图片走网络加载，需要已备案域名 + HTTPS + 配置 downloadFile 域名白名单

完成这些之后，仍然会因为 A-1、A-2 被驳回。**这条路本质上是走不通的。**

## 六、包名与体积处理建议（若选 B）

```bash
# 1. 注册并换取真实 AppID
#    改 miniprogram/project.config.json 的 "appid": "touristappid"

# 2. 压缩牌图到主包 2 MB 以内（目标：单张 ≤ 20 KB）
cd research-tarot/miniprogram/assets/cards
for f in *.jpg; do sips -Z 300 "$f" --out "$f" >/dev/null; done   # 尺寸
# 再用 cwebp 或 sips 的 JPEG 质量参数压到目标体积

# 3. 后台配置隐私保护指引（声明不收集用户信息）
# 4. 新增 pages/about/about：用户协议 + 免责声明 + 反馈入口
# 5. 首页与分享文案去占卜化
# 6. 开发者工具上传 → 公众平台提交审核
```

## 七、一句话建议

**这个东西作为「网页/H5」发布完全没问题，作为「微信小程序」发布在当前规则下几乎不可能过审**——不是配置没填好，而是「抽牌 + 判吉凶」这个玩法本身写在平台的禁止清单里。
